================================================================
  UTAU_VChat 文档发布 —— 上传步骤
================================================================

这个文件夹里是**只含介绍与描述文档**的版本，不含软件本体。
可以直接把这个文件夹作为 git 仓库的根目录。

  README.md            项目主页（已加「开发中，暂不提供下载」状态说明）
  项目介绍.md           四个长度的项目介绍，可按场合取用
  更新预告_v1.1.md      v1.1 的功能预告（语音 API 中转 / 自定义角色卡 / 自定义歌姬）
  首次使用必读.txt       面向用户的使用说明
  LICENSE              MIT 许可证
  .gitignore           防误传保护（重要，见文件内注释）


----------------------------------------------------------------
  一、准备
----------------------------------------------------------------

1) 装 Git：https://git-scm.com/download/win
   装完打开「Git Bash」或 PowerShell，确认能用：

       git --version

2) 注册 GitHub 账号：https://github.com/signup

3) 在 GitHub 网页上新建仓库：
   - 右上角 + → New repository
   - Repository name：UTAU_VChat
   - 选 Public 或 Private（都行，Private 也能随时改公开）
   - **不要**勾选 "Add a README file"（我们本地已有）
   - Create repository

4) 首次使用要告诉 Git 你是谁（只需做一次）：

       git config --global user.name  "你的名字"
       git config --global user.email "你的邮箱"


----------------------------------------------------------------
  二、上传
----------------------------------------------------------------

在本文件夹里打开终端（按住 Shift 右键 → 在此处打开 PowerShell / 终端），
依次执行：

    git init
    git add .
    git commit -m "docs: 项目介绍与更新预告"
    git branch -M main
    git remote add origin https://github.com/你的用户名/UTAU_VChat.git
    git push -u origin main

第一次 push 会弹出浏览器让你登录 GitHub 授权，跟着点就行。


----------------------------------------------------------------
  三、之后想改文档
----------------------------------------------------------------

    git add .
    git commit -m "docs: 更新了 xxx"
    git push


----------------------------------------------------------------
  四、将来要发布软件本体时
----------------------------------------------------------------

软件本体约 1.1 GB，**不要**直接 git add 进来 —— GitHub 单文件上限
100 MB，仓库也会变得极难维护。正确做法是：

  1) 把安装包/绿色版作为 **Release 附件**上传：
     仓库页 → Releases → Draft a new release → 拖入 exe/zip
  2) 仓库里只放源码，靠 .gitignore 把引擎/声库/发布包挡在外面
     （.gitignore 已经写好了）

届时把 .gitignore 顶部那段「只放行文档」的规则注释掉即可。


----------------------------------------------------------------
  五、三个容易踩的坑
----------------------------------------------------------------

1) **密钥泄漏**
   源码目录的 config.json 里有你的 DeepSeek API Key。
   千万不要把它提交上去。
   万一提交了 —— 删文件再提交**没用**，历史里还在。
   最快的补救是去 DeepSeek 后台**吊销并重新生成** Key。

2) **误传大文件**
   提交前用 `git status` 看一眼要传什么。
   如果列出来几百个文件、几百 MB，八成是把 _pkg/ 或 singers/ 加进来了，
   按 Ctrl+C 中断，检查 .gitignore。

3) **声库版权**
   重音テト / 足立レイ / VOICEVOX 语音模型的条款**不允许随意再分发**。
   这也是不该把它们提交进公开仓库的原因之一。
